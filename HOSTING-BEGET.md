# Сайт на Beget (Sprut.io) и ошибка «not found» / 404

## Почему так

Файловый менеджер **[Sprut.io на Beget](https://sprutio.beget.com/)** нужен, чтобы **загрузить HTML/CSS/JS** на хостинг.  
Он **не запускает** программу **Node.js** (`server.js`).

Личный кабинет и админка обращаются к адресам вида **`/api/...`**.  
На обычном виртуальном хостинге такого адреса **нет** → сервер отвечает **404 Not Found** («не найдено»).

То есть: **только залить файлы недостаточно** — нужен ещё работающий **backend** (тот же проект с `npm start` или аналог на другом сервисе).

---

## Что можно сделать

### Вариант 1 — API отдельно, сайт на Beget (часто проще всего)

1. Поднять **Node.js** где угодно, где умеют держать процессы 24/7, например:
   - [Railway](https://railway.app), [Render](https://render.com), [Timeweb Cloud](https://timeweb.cloud) и т.п.
2. Там залить весь проект, задать команду запуска **`npm start`**, открыть выданный URL (например `https://xxx.up.railway.app`).
3. В файле **`site-config.js`** на Beget прописать:
   ```js
   window.TR_API_BASE = "https://xxx.up.railway.app";
   ```
4. Снова залить обновлённый `site-config.js` через Sprut.io.

Тогда страницы с Beget будут звать API на этом адресе.

**Важно:** на стороне API в `server.js` уже включён **CORS** — запросы с вашего домена Beget должны проходить. Если что-то режет браузер — напишите свой домен, подстроим CORS.

---

### Вариант 2 — Всё на сервере с Node.js

Если у вас **VPS** или тариф, где можно поставить Node и держать процесс — сайт и `server.js` должны быть **на одном домене** (или настроен прокси с `/` на статику и `/api` на Node).  
Тогда **`site-config.js`** можно оставить с пустым `TR_API_BASE`.

Уточнять возможности лучше в поддержке Beget для **вашего** тарифа.

---

### Вариант 3 — Только статика без Node (другой проект)

Тогда нужно **переписать backend на PHP + MySQL** под типичный хостинг Beget. Это уже **отдельная большая работа**, текущий `server.js` так не работает.

---

## Локальная проверка у себя на компьютере

```bash
npm install
npm start
```

Открыть в браузере: `http://localhost:3000/cabinet.html` и `http://localhost:3000/admin.html` — там API и страница на **одном** порту, всё находится.

## Кратко

| Где лежат файлы | Запущен ли `server.js` | Результат        |
|-----------------|-------------------------|------------------|
| Beget (Sprut)   | Нет                     | 404 / not found  |
| Beget + `site-config.js` с URL API | API работает в другом месте | Должно работать |
| `npm start` локально | Да                 | Работает         |
